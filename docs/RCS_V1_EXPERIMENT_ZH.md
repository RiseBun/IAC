# IAC Response Consistency Score（RCS）v1

状态：2026-09-15 冻结。

## 1. 要回答的问题

RCS 只回答：在相同历史和相同随机因素下，改变导航命令后，WAM 的动作输出与生成视频中可恢复的相机转向是否产生同向响应。

它不证明“动作轨迹作为条件因果控制了视频”。如果视频分支和动作分支只是共同响应命令，RCS 仍然可以得分。这个因果边界必须保留。

## 2. 输入契约

每个反事实组必须包含 `left` 和 `right` 两个真实重生成分支，并满足：

- 相同 `counterfactual_group_id`、历史帧指纹、随机种子和 WAM 模型；
- 干预类型为 `navigation_command_onehot`；
- `future_images_source` 必须在冻结的原生生成来源白名单中；
- 两个分支的未来帧路径不能相同；
- 人为对比度退化等 `validation_only` 派生数据不得进入正式分数；
- 正式报告至少包含 30 个有效反事实组。

## 3. 视觉量与动作量

对每个左右分支，直接复用冻结 AS 视觉层：

- 视觉转向量：Reloc3r-512 从 `最后一张历史帧 + 4 张未来帧` 读取的累计 signed yaw；
- 动作转向量：WAM 原生四点轨迹计算的 action yaw。

对第 (i) 个反事实组：

\[
\Delta a_i = a_i^{left} - a_i^{right}, \qquad
\Delta v_i = v_i^{left} - v_i^{right}
\]

使用冻结死区将二者量化为 `negative / zero / positive`：

- 动作阈值：0.0128 rad；
- 视觉阈值：0.013317287876106008 rad，来自真实 NAVSIM 校准。

## 4. 正式分数

一个反事实组只有同时满足以下条件才记 1 分：

1. 动作差异超过阈值，即干预产生了实质动作响应；
2. 视觉差异也超过阈值；
3. 视觉响应与动作响应方向相同。

其余情况均记 0 分：

\[
RCS = 100 \times \frac{\sum_i
\mathbf{1}[q(\Delta a_i) \neq 0 \land q(\Delta v_i)=q(\Delta a_i)]}{N}
\]

这里的分母 (N) 是全部契约有效的声明干预对，而不是只挑出有明显响应的样本。

为什么零—零一致不计入正式分数：如果模型完全忽略左右命令，动作与视频都不变，三态一致率会达到 100%，但它没有表现出任何干预响应。零—零一致只报告为 specificity 诊断。

## 5. DriveWAM 正式结果

数据：修复 lineage 后的 Benchmark v3 DriveWAM 左右命令重生成，共 745 对。

| 量 | 结果 | 含义 |
|---|---:|---|
| 输入契约覆盖率 | 745/745 = 100% | 所有配对满足正式输入条件 |
| 实质动作响应覆盖率 | 369/745 = 49.5% | 左右命令让动作 yaw 真正拉开的比例 |
| 实质动作对上的视觉响应覆盖率 | 307/369 = 83.2% | 有动作差异时，视频也出现非零转向差异 |
| 检出视觉响应后的方向正确率 | 284/307 = 92.5% | 视觉响应一旦被读出，方向通常正确 |
| 实质动作对有效匹配率 | 284/369 = 77.0% | 未检出视觉响应也按失败计 |
| **正式 RCS** | **284/745 = 38.1/100** | 全部声明干预中形成正确非零协同响应的比例 |
| RCS 95% bootstrap CI | [34.8, 41.6] | 以反事实组为重采样单位 |
| 零动作响应 specificity | 333/376 = 88.6% | 动作未变化时视觉也未虚构变化 |
| 三态一致率（诊断） | 617/745 = 82.8% | 含零—零，不能作为正式 RCS |
| 视觉分支交换控制 | 6.2% | 左右视频交换后，实质动作方向匹配接近失效 |

另报告共同历史到第一张生成帧的边界差分，用于识别生成器的首帧跳变；它不改变正式 RCS。

结论：DriveWAM 在“已经产生实质动作差异”的样本上，视觉响应方向较可靠；正式 RCS 较低的主因不是方向读取错误，而是只有约一半声明左右干预真正拉开了动作输出。继续更换光流或相机运动读取器不会解决这一根因。

RCS 不继承 AS 的单片段历史—未来边界审计门禁。该审计仍记录在 RCS 报告中，但 RCS 的正式有效性由同历史、同随机种子、左右真实重生成的配对契约决定。原因是公共历史边界伪影在 left/right 差分中应当相消；若直接继承 AS 门禁，会把有效的反事实响应比较误判为无效。

## 6. Epona 正式结果

数据：Epona common-random 40 个同源组，共 40 对 left/right。动作干预来自 Epona 的真实轨迹注入，未来图像由同一随机数条件下分别重新生成；不含 logged 分支。

| 量 | 结果 | 含义 |
|---|---:|---|
| 输入契约覆盖率 | 40/40 = 100% | 所有配对均满足同历史、同种子和真实重生成 |
| 实质动作响应覆盖率 | 40/40 = 100% | 所有左右干预均拉开动作 yaw |
| 视觉响应覆盖率 | 38/40 = 95.0% | 大多数实质动作差异在视频中可观测 |
| 检出视觉响应后的方向正确率 | 35/38 = 92.1% | 检出响应时方向较可靠 |
| **正式 RCS** | **35/40 = 87.5/100** | Epona 的动作干预和视觉转向大多数同向响应 |
| RCS 95% bootstrap CI | [77.5, 97.5] | 以反事实组为重采样单位 |
| 动作—视觉响应幅度 Spearman | 0.192 | 方向响应可靠，但幅度排序不可靠 |
| 视觉分支交换控制 | 7.5% | 交换左右视频后方向匹配基本失效 |

排除历史→第一张生成帧、只看未来帧之间三段运动时，Epona RCS 为 90.0/100（36/40）；与正式 87.5/100 接近，说明首帧边界跳变没有主导结论。

Epona 的 AS 单片段 lineage 审计为 warning/failed（历史到第一张生成帧的边界几何覆盖较低），但 RCS 的左右配对契约完全通过。该差异是预期的：AS 需要判断单条历史—未来序列是否适合绝对评分，RCS 只判断同源左右分支的差分响应。

## 7. 跨模型解释

| 模型 | 正式 RCS | 动作干预覆盖率 | 检出视觉响应率 | 检出后的方向正确率 | 主要瓶颈 |
|---|---:|---:|---:|---:|---|
| DriveWAM | 38.1 | 49.5% | 83.2% | 92.5% | 左右命令经常没有拉开原生动作输出 |
| Epona | 87.5 | 100% | 95.0% | 92.1% | 方向可靠，幅度排序弱 |

因此 RCS 不应只看一个数字：DriveWAM 的 38.1 主要是干预执行覆盖问题，Epona 的 87.5 才显示出完整的响应链；两者在“已经检出视觉响应后的方向正确率”其实接近。

## 8. 纵向响应

纵向 progress 暂时只作诊断，不进入 RCS：

- 两个分支均具有四个有效纵向区间的覆盖率：181/745 = 24.3%；
- 有效对上的三态匹配率：23.2%。

这说明当前纵向探针无法可靠区分同源左右干预的细小进度差。扩大允许误差只会把更多样本压成零—零，不能增加非零响应证据。

## 9. 其他 WAM 的状态

- WorldDrive 当前只有 5 对，探索性 RCS 为 40.0，但 95% CI 为 [0, 80]，样本不足，禁止写成正式模型结论；
- 旧 DriveWAM 348 条使用人为对比度退化，现协议会拒绝；
- Epona 和 DriveVA 现有记录尚未经过同一冻结 Reloc3r-512 AS 层与本输入契约，旧光流 RCS 不能与 v1 横向比较。
