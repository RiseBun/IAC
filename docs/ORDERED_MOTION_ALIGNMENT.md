# Ordered Motion Alignment: portable IAC failure audit

## Status

This is an opt-in research module for diagnosing and improving the trusted IAC
mainline. It is not an official IAC result and is not, by itself, a paper
novelty claim.

The module tests one concrete hypothesis raised by the released clean V-JEPA
gate: downstream trajectory cross-attention followed by mean pooling can use
visual content while still lacking an explicit trajectory-segment-to-video-time
correspondence.

## What changes

The visual estimator remains candidate-blind:

```text
ordered V-JEPA tokens
  -> local monotonic temporal alignment
  -> per-segment visual motion estimate and uncertainty

candidate trajectory
  -> deterministic per-segment motion target

visual estimate vs candidate target
  -> longitudinal / lateral / heading / path-shape residual ledger
  -> non-negative additive mismatch energy
```

The candidate trajectory and source label are never inputs to the visual
network. Source labels are used only to select GT supervision during training,
choose fusion hyperparameters on validation, and report stratified metrics.

The four candidate target channels are:

1. longitudinal displacement `dx`;
2. lateral displacement `dy`;
3. heading change;
4. curvature as path-shape evidence.

For fixed-rate trajectories, the ordered `dx` sequence contains the
fine-grained speed and acceleration evidence that is lost by final-displacement
only heads.

## Existing cache compatibility

The module consumes the existing `x_tokens` cache generated by
`tools/extract_vjepa_video_features.py --token-summary-size 16`.

In the Hugging Face V-JEPA2 implementation, the Conv3D tubelet output is
flattened from `(time, height, width)`. The included extractor averages
contiguous token chunks. Under the mainline 64-frame/16-summary configuration,
the resulting 16 entries therefore preserve chronological tubelet regions.

The old clean gate is permutation-invariant after this compression. The new
module assigns explicit time positions and uses a local temporal band before
producing segment evidence.

Do not use a cache whose token ordering or `x_tokens` construction differs
without first auditing its metadata and extractor.

## Required local assets

No asset needs to be uploaded to another server. The run needs local paths to:

- train, validation and evaluation JSONL rows;
- their existing V-JEPA `x_tokens` caches;
- Python with PyTorch.

The rows need stable `sample_id`, `group_id`, `source_type` and
`candidate_traj`. GT rows should use `source_type=gt_pos` unless
`--positive-selector label_or_gt` is selected.

The optional raw-frame controls additionally need the local image root and
V-JEPA2 backbone already available on the machine.

## One-command server run

From the repository root:

```bash
nohup env \
  TRAIN_ROWS=/local/train_rows.jsonl \
  TRAIN_CACHE=/local/train_vjepa.pt \
  VAL_ROWS=/local/val_rows.jsonl \
  VAL_CACHE=/local/val_vjepa.pt \
  EVAL_ROWS=/local/holdout_rows.jsonl \
  EVAL_CACHE=/local/holdout_vjepa.pt \
  OUT_DIR=work/ordered_motion_holdout \
  bash scripts/run_ordered_motion_alignment_audit.sh \
  > work/ordered_motion_holdout.nohup.log 2>&1 &
```

This command continues after SSH disconnects. It does not install packages,
upload data, shut down the server, or change the default IAC scorer.

For validation-only tuned fusion with an existing IAC score:

```bash
VAL_PRIMARY=/local/val_iac_scores.jsonl \
EVAL_PRIMARY=/local/holdout_iac_scores.jsonl \
PRIMARY_KEY=iac_consistency
```

These variables can be added to the same `env` command. Fusion parameters are
selected on validation only and then frozen for evaluation.

To run the expensive raw-frame temporal controls locally:

```bash
RUN_RAW_FRAME_CONTROLS=1 \
IMAGE_ROOT=/local/image/root \
VJEPA_MODEL=/local/facebook_vjepa2_vitl_fpc64_256
```

If `VJEPA_MODEL` is omitted, Transformers uses
`facebook/vjepa2-vitl-fpc64-256`, which may require network access.

## Outputs to send back

The script creates `<OUT_DIR>_results.tar.gz`. It deliberately excludes the
large raw-frame control caches. The small archive contains:

- trained lightweight alignment model;
- validation and evaluation summaries;
- per-candidate evidence scores;
- compressed-token order and identity audit;
- failure ledger;
- optional raw-frame control comparison;
- optional validation-tuned fusion result;
- SHA256 manifest and run status.

Only this result archive and the `nohup` log need to be transferred.

## Required controls

The downstream audit includes:

- compressed visual time reversal and permutation;
- trajectory segment reversal and permutation;
- within-group Sattolo candidate derangement;
- cross-group visual derangement.

Raw-frame reversal and shuffle are separate because reversing already-extracted
tokens cannot test whether the frozen V-JEPA encoder contains temporal
information.

## How to judge the result

A useful result should satisfy all of the following on held-out drives:

1. normal ranking is better than candidate and visual derangement controls;
2. raw-frame and trajectory-segment order controls materially change evidence;
3. speed/acceleration and time-shift errors improve without reducing overall
   acceptable Top-1 or MRR;
4. the evidence ledger activates the expected family for single-factor
   counterfactuals;
5. validation-tuned fusion remains beneficial on untouched evaluation splits.

If only the training loss improves, or if derangement performs as well as the
normal mapping, the hypothesis is not supported.

## Scientific boundary

This implementation operationalizes a candidate direction:

> explicit ordered, candidate-verifiable and additive visual motion evidence.

It does not prove that V-JEPA lacks temporal information, does not establish
official IAC performance, and does not claim that speed counterfactuals are
solved. A paper claim requires the official IAC splits/checkpoints, multiple
seeds and the controls above.
